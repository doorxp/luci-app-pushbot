# 外网入站连接告警设计

## 意图与目标

为 PushBot 增加可选的“外网入站连接警告”。当防火墙允许一个新的 TCP 或 UDP 连接从 WAN 进入 LAN 时，立即推送外网来源 IP/端口、实际内网目标设备名及其 IP/端口；同时支持 IPv4 DNAT 端口转发和 IPv6 直连。

## 范围

- 新功能默认关闭，在 LuCI“配置 → 推送内容”中提供名为“入站警告提醒”的独立开关。
- 使用 `conntrack -E` 监听新建连接事件，并按 OpenWrt 防火墙 zone 判断连接是否为 WAN → LAN。
- IPv4 DNAT 从 conntrack 原始/应答元组还原外网来源与 NAT 后的 LAN 目标；IPv6 直连使用原始目标。
- 内网目标设备名优先使用 PushBot 已配置的设备别名，其次使用 DHCP 主机名；均无法解析时显示“未知设备”。设备名仅作辅助信息，始终保留目标 IP 与端口。
- 仅处理 TCP、UDP 的新连接；同一 conntrack 连接只推送一次。
- 推送复用现有渠道、消息格式、设备名称和免打扰策略；日志记录是否推送或因免打扰跳过。
- 服务启动、停止、重启时同步管理监听进程，防止孤儿进程和重复监听。
- 软件包增加 `conntrack` 运行依赖；旧配置升级后保持关闭，不改变现有行为。

## 非目标与防误报

- 不推送被防火墙拒绝的扫描或连接尝试。
- 不监控路由器自身的 WAN INPUT 连接，只监控转发进入 LAN 的连接。
- 不对来源做地理位置查询，不自动封禁来源 IP，不提供端口或 IP 过滤规则。
- 无法确认 WAN → LAN 方向、缺少必要元组字段或协议不是 TCP/UDP 时不推送。

## 方案比较

- **已选：conntrack 实时事件监听。** IPv4/IPv6 覆盖完整、延迟低，代价是增加 `conntrack` 依赖，并需要可靠解析 NAT 前后元组与 zone。
- **未选：轮询 `/proc/net/nf_conntrack`。** 无新增依赖，但短连接可能漏报，且通知受主循环间隔影响。
- **未选：注入 nftables/iptables 日志规则。** 接口方向精确，但 fw4/fw3 差异和防火墙重载恢复使维护成本及兼容风险更高。

## 验收标准

- 启用后，IPv4 端口转发的新 TCP/UDP 连接推送外网来源，以及 NAT 后内网目标的设备名、IP、端口。
- 启用后，IPv6 WAN → LAN 新连接推送来源，以及目标设备名、IP、端口。
- 设备别名存在时优先显示别名；无别名时显示 DHCP 主机名；两者均无时显示“未知设备”。
- LuCI“配置 → 推送内容”显示“入站警告提醒”开关；关闭时不监听、不推送，旧配置升级后保持关闭。
- LAN 内部连接、LAN 出站连接、路由器自身 INPUT、被拒绝流量、非 TCP/UDP 流量均不推送。
- 禁用时不启动监听；重启服务不会留下或创建重复监听器。
- 现有配置保存、重置、推送渠道及其他提醒功能不回归。

## 实现者可自行决定

- conntrack 行文本的具体解析函数拆分方式。
- 临时 FIFO、PID、事件队列文件在 `/tmp/pushbot/` 下的准确命名。
- 在保持 BusyBox/OpenWrt shell 兼容前提下的测试夹具结构。
